# Building and testing shex.js

shex.js is an npm-workspaces monorepo (`packages/*`). Every package is
TypeScript: `src/*.ts` compiles with `tsc` into `lib/*.js`. Tests are mocha
files at `packages/*/test/*test.js`, run from the **repository root**.

## Build

| Command | What it does |
|---|---|
| `npm ci` / `npm install` | also runs `prepare`: installs the husky hooks, then `make ALL` |
| `npm run compile` | `make ALL`: every package's `src/` → `lib/`, both jison parsers, and the web apps' committed page scripts |
| `make page-scripts` | rebuild the page scripts unconditionally |
| `npx tsc` (in a package) | rebuild just that package |
| `npm run watch` (in shex-webapp, extension-map, extension-reduce) | `tsc -b --watch` over the package's tsconfigs: `lib/` and its page scripts together. Its `.tsbuildinfo` files go in the package's `node_modules/.cache/tsc/` |
| `npm run parser` (in `packages/shex-parser` or `packages/shape-map`) | regenerate `lib/ShExJison.js` / `lib/ShapeMapJison.js` from the `.jison` grammar |
| `npm run parser-all` | both parsers |

- **`lib/*.js` is gitignored build output** (see `.gitignore`). The sources in
  `lib/` are tracked: the `.jison` grammars, `.wat`/`.wasm`, and shex-cli's
  hand-written `ExitCode.js`, `ProgressLoadController.js`, `ShExDebugRepl.js`
  and `ShExRWriter.js`. Everything else under `lib/` gets overwritten.
- **Builds survive `git checkout`, `pull` and `merge`.** After any of these,
  run `npm run compile` before you trust a test result. A stale `lib/`
  silently runs the old code. It can **hang** the suite instead of failing
  (e.g. an infinite loop that was fixed in `src/` but not rebuilt), which
  looks like "the next test is broken" or "my fix got reverted". Before you
  debug, compare `lib/` and `src/` mtimes, or grep `lib/` for the fix.
- **The `Makefile` is a table**, one line per package in dependency order:
  `$(eval $(call package,DIR,OUTPUT,UPSTREAM...))`. A package rebuilds when
  any `src/*.ts`, its `package.json`/`tsconfig.json`, or an upstream
  package's output changes. **Adding a package or a workspace dependency
  means editing its line.** `packages/shex/test/Makefile-test.js` (part of
  `npm test`) fails until the table matches every `package.json`'s runtime
  dependencies, is in dependency order, and sees every source. A build that
  is more than `tsc` sets `BUILD.<dir>`. Inputs outside `src/` get an extra
  prerequisite line under the table.
- `make ALL` runs `tsc`/`ts-jison` from `node_modules/.bin`, so it works from
  any shell. It uses GNU make 3.81 features only (macOS ships 3.81). That
  make compares mtimes to the second, so a file touched in the same second as
  its output looks up to date.
- `make ALL` also rebuilds the web apps' **committed** page scripts
  (`doc/*.js` from `src/app`, `src/worker` and `src/plugin`); commit them with
  their sources. It does not build the webpack bundles. The shexjs-webapp
  skill covers both.
- **Types point at source**: each package's `types` is `./src/<name>.ts`.
  No `.d.ts` is emitted. The hand-written ones (`shex-term/shexv.d.ts`,
  `shex-webapp/shex-webapp.d.ts`, the `untyped-modules.d.ts` shims) aren't
  checked against the code. Treat them as possibly stale.
- The parsers are generated by `@ts-jison` (the Makefile uses `-p lr` for
  ShExC and `-p lalr` for ShapeMap, like the package scripts). Edit the
  `.jison` file, never the generated `.js`.

## Test

```sh
npm test                                   # ungated suite, ~20 s, ~6800 tests
npx mocha packages/shex-parser/test/ParserOptions-test.js     # one file
TESTS='^1dot_pass-noOthers$' npx mocha packages/shex-validator/test/Validation-test.js
VERBOSE=1 npx mocha packages/shex-cli/test/Parser-Writer-test.js
```

- **`TESTS` has no single syntax.** Each file parses it its own way. Read the
  top of the file:
  - `Validation-test.js`, `ValidationContrib-test.js`,
    `Sparql-Validation-test.js`: a regex over the test `@id`, schema and data.
  - `Parser-Writer-test.js`, `SemActs-test.js`, `Loader-test.js` and most
    other shex-cli/util/node tests: a comma-separated list of exact names.
  - `Map-test.js`, `ThreadedMaterializer-test.js`: a `|`-separated list.
- Validation tests run under both regex engines, so one test id gives
  2 passing.
- `VERBOSE` (any value) makes several harnesses print their inputs,
  results and expected values.
- The shexTest corpus location (`TESTSDIR`, `../shexTest`, …) and `.val`
  regeneration (`REGEN=1`) are covered in the shextest-paired-branches skill.

### TEST_* gates

`npm test` skips whole suites unless you set their gate. Each skipped suite
prints a `Skipping …` warning or shows up as a pending test.

| Gate | Enables | Needs |
|---|---|---|
| `TEST_cli=true` | shex-cli `Cli-test`, `Stdin-test`, `Debug-cli-test`; extension-map `Map-cli-test` | nothing extra |
| `TEST_server=true` | shex-cli `Server-test`, `Server-extra-test` | local ports |
| `TEST_browser=true` | jsdom smoke tests in shex-webapp, extension-map, extension-reduce | **the webpack bundles** (see the shexjs-webapp skill); Node ≥ 22 (jsdom) |
| `TEST_sparql=true` | neighborhood-sparql `Sparql-Validation-test`, `Sparql-Bnode-test` | a built-in comunica endpoint, or `SPARQL_ENDPOINT=<url>` |
| `TEST_wikidata=true` | a live wikidata.org smoke test in `Wikibase-Db-test` | network |
| `TEST_network=true` | network-dependent examples in `shex/test/Readme-examples-test` | network |

- **The gated suites hide their own fixtures.** A change to validation
  output can pass `npm test` and still break a `.val` or expected output
  behind `TEST_cli`. Before you call an output-changing change clean, run
  `npm run test-all` (every gate) or at least `npm run test-no-browser`.
- **Without the bundles, `TEST_browser` fails in a misleading way.** It gives
  about two dozen `ReferenceError: N3js is not defined` /
  `ShExWebApp is not defined` failures. They look like broken app code, but
  they all come from the missing bundles.
- Every gate is read by `packages/shex-cli/test/testGate.js`: `true`, `1`,
  `yes`, `on` enable it; `false`, `0`, `no`, `off` or empty disable it
  (case-insensitive); anything else throws. **A new gate should use it**:
  `require("../../shex-cli/test/testGate.js")("TEST_x")` (an optional second
  argument is the default when the variable is unset).
- `npm run test-sparql` runs only the SPARQL suites.
- CI (`.github/workflows/ci.yml`) runs `npm ci`, `npm run compile`,
  `npm run webpacks-all` and `npm run test-all` on Node 22/24/26, and
  `test-no-browser` on Node 20. Its lint job also runs `check-branch-deps` and
  `check-page-scripts` (the committed page scripts must match their
  TypeScript).

## Pre-commit hook

Husky (`core.hooksPath=.husky/_`, installed by `prepare`) runs
`.husky/pre-commit`:

```sh
npm run lint && npm run test && npm run check-branch-deps
```

- `lint` is eslint on `packages/shex-cli/test/findPath.js` only.
- `test` is the **ungated** suite (~20 s). It doesn't compile first, so a
  stale `lib/` gets tested.
- `check-branch-deps` (`tools/checkBranchDeps.sh`) fails on `main` unless
  the `shex-test` devDependency is `github:shexSpec/shexTest#main`.
- `HUSKY=0 git commit …` skips the hook. Do that only when you've already run
  the relevant suites.

## Coverage

`npm run coverage` runs `c8 npm run test-all`, with config in `.c8rc.json`.
c8 follows worker threads and child processes, and uses the tsc source maps
to report against `src/*.ts`. Reports (`lcov` and `text`) go to `coverage/`,
which is gitignored (`coverage/lcov.info` feeds Coveralls in CI). It needs
everything `test-all` needs: bundles, a SPARQL engine and network. For a
quicker partial number, use
`npx c8 mocha packages/<pkg>/test/*test.js -R dot` on a subset.
